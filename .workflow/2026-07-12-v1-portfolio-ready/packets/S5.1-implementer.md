# Packet S5.1 — implementer

## Objective

Dockerfiles + four-container compose (web/worker/batch/postgres) per SPEC §4.4 / SPEC_V3 §9.

## Context

- Current `docker-compose.yml` is **Postgres-only** (`ankane/pgvector`); no application Dockerfiles exist.
- SPEC §4.4 requires compressed four-container topology:

| Container | Modules |
|---|---|
| `web` | analyst-ui, ingest API, explainer API, containment queue API |
| `worker` | scorer, decision-recorder, entity-resolver |
| `batch` | profile-builder (DuckDB), eval-harness, replay-runner, synthetic-generator |
| `postgres` | Postgres + pgvector |

- Local-only: no public ingress, no external auth, no TLS in v1 (document as production upgrade if mentioned).
- kind/k3d manifests are nice-to-have if time; compose + Dockerfiles are the acceptance bar.
- App entry: `uvicorn web.api:app`; Python package via `pip install -e ".[dev]"` / `pyproject.toml`.

## Write scope (`files_allowed`)

- `Dockerfile` / `Dockerfile.*` / any `Dockerfile*` at repo root or under a small `deploy/` layout if needed
- `.dockerignore` (if needed for build context)
- `docs/` (deployment notes / playbook; keep claims honest)

## Acceptance criteria

1. One or more Dockerfiles build images usable for `web`, `worker`, and `batch` (shared base image OK if roles differ by command).
2. `docker-compose.yml` defines **four** services matching SPEC names/roles: `web`, `worker`, `batch`, `postgres` (postgres may keep pgvector image).
3. `web` exposes the FastAPI/analyst surface (`uvicorn web.api:app` or equivalent); `worker` and `batch` have documented run commands suitable for local portfolio demos (even if worker is a sleep/loop stub documented as placeholder, prefer a real module entry if one exists).
4. Services wire `DATABASE_URL` (or equivalent) to the compose postgres service; credentials stay local-dev defaults (document; no secrets committed beyond existing pattern).
5. Docs under `docs/` describe how to bring the four-container stack up and what each container runs; do not claim K8s/kind shipped unless manifests are actually added.
6. `.dockerignore` (or equivalent) keeps build context lean (exclude `.git`, `__pycache__`, local `*.db`, etc.).
7. Do **not** require a live `docker build`/`compose up` if the environment cannot pull images — still produce valid Compose YAML + Dockerfiles. If `docker` is available, prefer `docker compose config` validation.

## Constraints

- Do **not** mark the queue/state packet `done`.
- Do **not** run S5-EXIT-GATE / phase exit verification.
- Stop and report `approval_gates` before dependency installs (`pip install`, `npm install`), `.codex`/`.claude` edits, clones, writes outside `files_allowed`, or destructive git.
- Pulling base images / `docker compose up` that mutates a shared DB is an approval gate — skip live up unless already approved; file artifacts are enough.
- Smallest safe diff; match existing repo style.
