## Context

- SPEC requires low-trust strings (process command lines, file paths, URLs, free-text log fields) to be **escaped, length-capped, and slot-isolated** (e.g. `<command_line>...</command_line>`), with the LLM instructed not to treat slot contents as instructions.

## Acceptance criteria

1. Low-trust values from decision/profile/event context (at least: command lines, file paths, URLs, and any free-text feature values) are placed in labeled delimited slots (e.g. `<command_line>...</command_line>`), not concatenated into free-form prompt prose.
2. Values in those slots are escaped (so `</command_line>` and similar cannot break out) and length-capped (document the cap; pick a reasonable constant consistent with SPEC “length-capped”).
3. Prompt text explicitly instructs the model not to interpret slot contents as instructions.
4. High-trust / structured fields remain named bindings (JSON or equivalent), not mixed into low-trust slots.
5. Tests cover: (a) a malicious low-trust string does not appear outside its slot and cannot inject a closing tag that escapes the slot; (b) length cap is applied; (c) existing template-fallback / prohibited-content tests still pass.
6. `pytest tests/worker/test_explainer.py -v --tb=short` passes.
