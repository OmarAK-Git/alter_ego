# Packet S4.5 — implementer

## Objective

First-class `replay_run_id` on decisions / audit path (SPEC §6.2 / §9.3).

## Context

- `batch/replay_runner.py` currently prefixes `decision_id` and stuffs `replay:{id}` into `flags` — not a first-class field.
- SPEC DecisionRecord includes `replay_run_id` (null if original; populated for replays).
- Original decisions must remain immutable; replays create new records linked by `replay_run_id`.

## Acceptance criteria

1. `DecisionRecord` (Pydantic) has optional/nullable `replay_run_id`.
2. ORM / persistence stores `replay_run_id` (nullable) on decision records.
3. `run_replay` sets `replay_run_id` on newly emitted decisions (not only via flags prefix).
4. Original (non-replay) decisions have `replay_run_id` null/absent.
5. API responses that return decision detail include `replay_run_id` when present.
6. Tests cover schema + replay population; focused pytest passes.
