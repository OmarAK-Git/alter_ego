## Design choices

- **Failure signal:** structured `AuditIntegrityResult` dict printed to stdout; `logger.error` with payload; **non-zero exit (1)** from `python -m batch.audit_integrity`; optional `raise_on_failure=True` → `AuditIntegrityError` for programmatic callers.
- **Count check:** compares `RECORD_DECISION` / `DECISION_RECORDED` audit rows vs `decisions` table count; skipped when no decision-audit actions exist (current production path — audit not yet wired to every decision).
- **Chain check:** walks `audit_logs` ordered by `log_id`; each `previous_log_hash` must equal prior row's `compute_hash()`; first row must have `previous_log_hash is None`.

## CLI usage

```bash
# Local / cron
python -m batch.audit_integrity

# Docker compose (batch idle container)
docker compose exec batch python -m batch.audit_integrity
```

On success: JSON with `"ok": true`, exit 0. On failure: JSON with `breaks` / `count_mismatch`, exit 1.
