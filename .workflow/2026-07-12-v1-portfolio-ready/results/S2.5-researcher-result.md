# S2.5 Researcher Result — Frozen Cohort-Prior Artifacts

**Date:** 2026-07-13  
**Question:** What exists today for frozen cohort-prior snapshots vs SPEC_V3? Recommend ship (A) or downgrade (B).

## Recommendation: **B — Downgrade SPEC_V3**

Document that **v1 uses profile-embedded `cohort_data` only**. Independent versioned frozen cohort-prior artifacts are **deferred** (post-v1 / Phase 4 hardening). Do **not** ship a stub table or fake `cohort_builder` that still duplicates histograms into every profile while claiming independence.

### Justification (portfolio bar)

| SPEC_V3 claim | Today |
|---|---|
| "Cohort builder writes versioned frozen cohort-prior artifacts on an independent cadence" (`docs/SPEC_V3.md:79`) | **No cohort builder module.** Cohorts computed inline inside `build_profiles()` on every profile build (`batch/profile_builder/builder.py:157-187`). |
| "Scorer selects … a frozen cohort snapshot for the scoring window" (`docs/SPEC_V3.md:81`) | Scorer reads `profile.features["cohort_data"]` only (`worker/scorer.py:209-219`). `ProfileStore.get_active_profile` is the sole artifact selector (`worker/profile_store.py:12-48`, `worker/scorer.py:503`). |
| Exit gate: "Frozen cohort-prior snapshots exist" (`docs/SPEC_V3.md:263`) | **Not met** as independent artifacts. Cohort histograms exist only as JSON inside `ProfileArtifactModel.features`. |
| "Cohort priors … independent of profile builds" (`docs/SPEC_V3.md:191`) | Same `as_of`, same 30-day DuckDB window, same build invocation as profiles. |

Shipping real independence (minimal honest scope) requires at least:

1. **ORM + migration** — new `cohort_prior_artifacts` table (version, `as_of`, `data_window_start/end`, `promoted_at`/`superseded_at`, frozen histogram JSON).
2. **`batch/cohort_builder/`** — extract DuckDB cohort queries from profile builder; run on separate cadence.
3. **`worker/cohort_store.py`** — point-in-time cohort selection mirroring `ProfileStore`.
4. **`worker/scorer.py`** — load cohort via `CohortStore`, not `profile.features["cohort_data"]`; add `cohort_version` to `compute_decision_id` payload for determinism.
5. **Profile builder** — stop embedding duplicate `cohort_data` (or document transitional dual-read).
6. **Tests** — PIT cohort selection, scorer uses cohort artifact when profile predates cohort update, decision lineage includes `cohort_version`.

That is a **medium sprint**, not an S2.5 packet. A hollow stub (empty table + still embedding in profiles) would misrepresent portfolio readiness. `memory-bank/progress.md:55` already records the honest gap.

**What works today without independent artifacts:** three-step fallback (local → role → terminus), novelty gate, `cohort_used` / `cohort_unsupported` on decisions. Functionally sufficient for v1 calibration; only the **independence / versioning** story is missing.

## Evidence — What Exists Today

### 1. Profile builder embeds `cohort_data`

During each `build_profiles()` run, DuckDB aggregates cohort histograms from the **same** 30-day historical event slice used for entity profiles:

- `batch/profile_builder/builder.py:157-163` — `parent_cohorts` and `primary_cohorts` via DuckDB `histogram()` grouped by `entity_type` / `role`.
- `batch/profile_builder/builder.py:165-166` — `global_cohort` (terminus).
- `batch/profile_builder/builder.py:187` — `cohorts = {"primary": primary_cohorts, "parent": parent_cohorts, "terminus": global_cohort}`.
- `batch/profile_builder/builder.py:311-318` — identical `cohort_data: cohorts` embedded in every entity profile features dict.

Shape:
- **`primary`**: `{role: {login_hours, endpoints, process_names, geolocations}}`
- **`parent`**: `{entity_type: {…}}` — built but **not consumed** by scorer
- **`terminus`**: global histograms

Verified by test: `tests/batch/test_profile_builder_geo.py:69-70`.

### 2. Scorer uses profile-embedded cohorts only

- `worker/scorer.py:209-219` — `_get_cohort_histogram` reads `profile.features["cohort_data"]`; fallback local (≥20 obs) → role (≥100 obs) → terminus.
- `worker/scorer.py:503-521` — `ProfileStore.get_active_profile` then `score_event(..., profile, ...)`. No cohort artifact lookup.
- `worker/scorer.py:32-51` — `compute_decision_id` includes `profile_version` but **no** `cohort_version`.
- `worker/scorer.py:265-322` — novelty gate queries live `ResolvedEventModel` via `_get_cohort_members`, not frozen priors.

### 3. No separate CohortPrior models / tables / files

`CohortConfig` (`core/schemas/config.py:9-11`) is scoring minimums only.
