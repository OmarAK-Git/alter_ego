## Decision summary

Ship the portfolio IaC gate by **recognizing existing `docker-compose.yml` as the v1 “Terraform or equivalent” IaC artifact** and aligning SPEC / SPEC_V3 / deployment docs. **Do not** add a `terraform/` wrapper that duplicates compose — that would be maintenance theater with drift risk and no added reproducibility.

Path B (downgrade §9 IaC gate) is unnecessary because SPEC_V3 §5 explicitly allows **equivalent** IaC, and S5.1 already delivered a version-controlled, reproducible four-container definition matching §4.4.

### Why not Path B (downgrade)

Path B (S4.7-style defer banners removing §9 IaC from binding gates) fits when **no honest artifact exists** and shipping would be greenfield theater.

Here, **`docker-compose.yml` is real declarative IaC**: version-controlled, `docker compose config` validatable, reproduces the four SPEC-named containers with the same roles as §4.4. SPEC_V3 §5’s **“or equivalent”** language was written for exactly this v1 local-first posture.

Downgrading would **weaken** a gate that can be closed honestly with existing artifacts plus doc alignment.

### Why not add `terraform/` (minimal Terraform ship)

| Approach | Cost | Honesty |
|---|---|---|
| `kreuzwerker/docker` provider managing 4 containers | Duplicate compose service defs; drift risk | Worse — two sources of truth |
| `null_resource` + `local-exec` calling `docker compose up` | Adds Terraform dep for zero capability | Theater |
| Doc-only: compose = equivalent IaC | ~5 file edits | Best — matches “or equivalent” |

`state.json` S5.2 lists `terraform/` as a possible source, but objective is **“Terraform or equivalent OR downgrade”** — compose satisfies equivalent.
