## Summary

`decision_id` is now derived from canonical sorted-key JSON serialization that includes `scorer_algorithm_version` and `embedding_model_version` per SPEC_V3 §6.1. A pinned module constant `SCORER_ALGORITHM_VERSION = "1.0"` and exported helper `compute_decision_id()` centralize the formula for both normal and staleness-halt paths.

## Formula

**Normal scoring path:**

```text
payload = {
  "embedding_model_version": <profile.embedding_model_version>,
  "event_id":                <resolved_event.event_id>,
  "profile_version":         <profile.profile_version>,
  "scorer_algorithm_version": SCORER_ALGORITHM_VERSION,  # "1.0"
  "scoring_config_version":  <str(config["version"])>,
}
canonical = json.dumps(payload, sort_keys=True, separators=(",", ":"))
decision_id = sha256(canonical.encode("utf-8")).hexdigest()
```

**Staleness-halt path:** same payload plus `"halt": true` (boolean) so halt decisions remain idempotent but distinct from scored decisions.

Example canonical string (normal):

```json
{"embedding_model_version":"1.0","event_id":"evt_123","profile_version":"prof_v1","scorer_algorithm_version":"1.0","scoring_config_version":"1.0"}
```
