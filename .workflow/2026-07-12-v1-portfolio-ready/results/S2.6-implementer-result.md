Deferred because:

1. Packet preference: honest strip unless implementation is clean **and** tested **and** calibration-ready.
2. Activating a new scoring signal without an S3 eval sweep would change production scores under frozen weights — violates eval-first discipline.
3. `docs/SPEC.md` §6.2 never listed `total_volume_delta` in the six-feature contract; README was the main overclaim.

### What strip/defer does

- README no longer lists `total_volume_delta` as an active calibrated feature; deferred note added.
- YAML weight **kept** (1.0) with explicit deferred comment — no weight/threshold change.
- Scorer still emits a `total_volume_delta` contribution row at `0` with flag `volume_delta_deferred` (renamed from `volume_delta_suppressed_no_current_count`).
- `memory-bank/progress.md` inventory: `wire` → `defer` for this knob; S2.6 closed.

**Not touched:** `state.json`, other feature weights, `anomaly_threshold`, `drift_threshold`, no commits.
