## Reward-hack / residual risks (did not refute)

1. **Scorer tests hardcode `resolution_confidence`** (`0.3` / `1.0`) and do not pipe `resolve_entity(...)` output into `score_event`. Fixture→flag is proven compositionally (resolver low conf + scorer flag wiring), not as a single end-to-end call.
2. **Split fixture is semantically thin**: `split::<ref>` is a clean 1:1 map with artificially low confidence; it does not model competing candidate identities. Acceptable as a Phase-1 deterministic fixture parallel to `collide::`, but weaker than AC2’s “ambiguous/conflicting” wording.
3. **Happy-path resolve test does not assert flag absence** — only confidence. Flag absence is covered by the separate scorer high-confidence test.
4. **Fail-before evidence** for TDD is not recoverable from the current tree; only pass-after was verified.

These weaken the “tests prove it” rhetoric but do not break the written acceptance criteria or the production wiring.
