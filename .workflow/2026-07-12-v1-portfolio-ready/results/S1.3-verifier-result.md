`containment_threshold` (sourced from YAML) gates automatic `ContainmentQueueModel`

## Independent evidence

### 1. Scorer flag logic — `worker/scorer.py:415-420`
```python
containment_threshold = config.get("containment_threshold", 85.0)
if (
    total_score >= containment_threshold
    and decision_confidence >= confidence_floor

    flags.append("simulated_containment_queued")
```
- Threshold is read from `config`, which is loaded from YAML via
  `load_scoring_config()` (`scorer.py:176-181`).
- Gate is a conjunction of score AND confidence, exactly as claimed.
- Below threshold → conjunction false → flag not appended → no downstream queue.
- Staleness early-return (`scorer.py:246-265`) exits before this block, so a
  halted decision never sets the flag. Not a defect; consistent with intent.

### 2. YAML source — `config/scoring_config.yaml:19`
`containment_threshold: 85.0` — present, matching the test expectation.

### 3. Recorder queue helper — `worker/recorder.py:7-18, 44-50`

- Queue write is triggered solely by the exact flag string the scorer appends

- **Weakened assertions?** No — tests assert the real gates: `score < 85.0`,

- **Flag string mismatch?** No — identical literal on scorer and recorder sides.

## Residual note (non-blocking, not a refutation)

are verified independently (scorer sets flag; recorder writes on flag). Because
the composition is trivial and the flag contract is exact on both sides, this
does not undermine the claim, but a full-path integration test would harden it.
