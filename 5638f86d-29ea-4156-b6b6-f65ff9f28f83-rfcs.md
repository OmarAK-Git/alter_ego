**Severity:** S2 | **Scope:** behavior | **Personas:** hostile_pr_reviewer

### Problem

## RFC-as-built-md-002: Prevent Attacker Persistence via Profile Builder DoS

**Severity:** S1 | **Scope:** behavior | **Personas:** attacker

### Problem
Disrupting the batch profile builder causes silent scoring bypass rather than alerting. If no profiles are built for 14 days, events trigger 'staleness_halt' and are scored as 0 (is_anomaly=False). An attacker can DoS the builder job to achieve undetected persistence.

### Evidence
- AS_BUILT.md:6 — max_profile_staleness_days: 14 ... score_event → score 0, staleness_halt, not anomaly
- AS_BUILT.md:7 — Fail-closed scoring | Stale profile ... → score=0, is_anomaly=False, halt flags

### Traceability
- novel: Fixed probes test for the invariant logic (staleness caps), but do not threat-model the operational consequence that returning score=0 for staleness creates a permanent evasion safe harbor during an availability outage.

### Proposed Change
Configure telemetry to trigger a high-severity alert for extended unavailability of the batch profile builder, and restructure 'staleness_halt' to log an operational threat rather than implicitly granting scoring safe harbor.

### Acceptance Criteria
- Extended failure of the profile builder beyond the staleness threshold generates a critical alert and does not automatically provide a silent safe harbor for event scores.

### Problem

### Evidence
